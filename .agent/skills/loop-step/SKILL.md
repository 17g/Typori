# Instructions:

1. `Plan.md` を読み、最初に見つかる未完了タスク（`- [ ]`）を1つ特定する。

2. 関連する `for\_agent/` の仕様を確認し、コードの実装・修正を行う。

3. `AGENTS.md` に記載された検証コマンドを実行し、エラーがない（Exit Code 0）ことを確認する。

 - 失敗した場合はエラーログを修正し、パスするまで繰り返すこと。

4. `AICHANGELOG.md` に今回の変更内容（Before/After、変更理由）を追記する。

5. `Plan.md` の該当タスクを `- [x]` に更新する。

6. Git コミットを作成する（例: `git commit -m "feat: ..."`）。

7. すべてのタスクが `- [x]` になった場合は「全タスク完了」と報告せよ。

8. 今回の会話セッションにおいて、今後のこのスキルを使ったループエンジニアリングでAIが同じエラーを繰り返さないための「アップデート用ナレッジ（システム指示）」を作成してください。

   1. ログから以下のパターンを特定し、リストアップしてください。
      1. **OS・シェル誤認によるコマンドエラー**:
         - POSIXコマンド（`rm -rf`, `ls`, `mkdir -p`など）をWindows（cmd/PowerShell）で実行して失敗した事例
         - Windows固有のコマンドやエイリアスをLinux（Debian等）で実行して失敗した事例
      2. **パス・構文エラー**:
         - パス区切り文字（`\\` と `/`）の混同、ドライブレター（`C:`）の不適切な扱い
         - 環境変数の参照形式（`$ENV` / `%ENV%` / `$env:ENV`）の間違い
         - コマンドチェーン（`&&`, `||`）やエスケープ処理のシェル間での非互換性によるエラー
   2. 1を行った結果として以下の2点を出力してください。

      1. エラー分析レポート

         頻発しているOS起因のエラーパターンTop 3と、誤って生成されたコマンド、およびその環境で本来実行すべきだった正しいコマンドの対比表。
      2. アップデート用ナレッジ（Markdown）

         システムプロンプトや、ハーネスが読み込むルールファイル（例: `GEMINI.md又はAGENT.md`）にそのまま組み込めるテキスト。以下の要素を必ず含めてください。

         - セッション開始時やコマンド実行前に、現在自分がどのOS・シェル環境にいるかを必ず確認・意識するための「思考プロセス（Chain of Thought）の強制ルール」
         - 環境非依存で操作するための原則（OSコマンドを直接叩かず、極力Pythonの`os`や`pathlib`等の標準ライブラリを使用してファイル操作を行う等の代替案）
         - よく間違えるコマンドの環境別マッピング表
